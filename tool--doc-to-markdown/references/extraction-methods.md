## Extraction Method Concepts

The per-format files above contain executable code and format-specific detail. This section explains the four fundamental extraction approaches so you can choose the right one before opening a format file.

---

### 1. Text-Layer Extraction (Native Text)

**What it is:** The source file (PDF, DOCX, EPUB) contains an embedded text layer — the actual Unicode characters are stored in the file and can be read directly without any visual interpretation.

**When to use it:** The file was created digitally (not scanned). A quick test: attempt `pdfplumber` on a PDF and check whether pages return non-empty text. If yes, the text layer exists.

**How it works:**
- PDF: `pdfplumber` reads the content stream character by character, preserving position data. `pypdf` is the fallback — less table-aware but faster.
- DOCX: `mammoth` reads the Open XML structure and converts to clean HTML, which is then converted to Markdown. Preserves bold, italic, heading styles, tables, and lists. `pandoc` is the alternative if mammoth is unavailable.
- EPUB: `ebooklib` unpacks the container and exposes individual HTML spine items; `BeautifulSoup` then extracts text from each.

**Strengths:** Fast, high accuracy, preserves structure (headings, lists, tables) if the source is well-formed.

**Failure modes:** Text layer can be garbled (ligatures rendered as wrong characters, copy-protection scrambling, missing font embedding). Always spot-check 5 passages against the source after extraction. See `extraction-pitfalls.md` for ligature and font issues.

---

### 2. OCR Extraction (Scanned or Image-Based Documents)

**What it is:** The file contains no text layer — only images of pages. Optical Character Recognition (OCR) reads the image pixels and infers characters.

**When to use it:** A PDF returns empty text on all pages when tested with `pdfplumber`. The file is a scanned document, a photographed page, or a PDF generated by a scanner or fax.

**How it works:**
1. `pdf2image` converts each PDF page to a high-resolution PIL Image (default 300 DPI for accuracy).
2. `pytesseract` runs Tesseract OCR on each image, returning a string per page.
3. Confidence data is available via `pytesseract.image_to_data()` — use this to flag low-confidence passages rather than silently delivering uncertain text.

**Quality gates for OCR output:**
- Flag any passage where Tesseract confidence is below 60% with `<!-- [OCR LOW CONFIDENCE]: ... -->`.
- For mixed-language documents, pass the correct `lang` parameter (e.g., `lang='ita+eng'`).
- Tables extracted via OCR are unreliable — flag every OCR-extracted table with `<!-- [TABLE WARNING]: OCR source — verify cell values against original -->`.

**Strengths:** The only viable path for scanned documents.

**Failure modes:** Accuracy degrades with low-resolution scans, handwriting, unusual fonts, skewed pages, and complex multi-column layouts. Always report OCR confidence in the quality assessment. Never deliver OCR output without flagging its uncertainty to the user.

---

### 3. Structured Extraction (Tables, Spreadsheets, Structured Data)

**What it is:** The source encodes data in a structured format (XLSX, CSV, JSON, XML, HTML tables) where the relationships between cells, rows, and fields are explicit in the file format itself.

**When to use it:** The file is a spreadsheet, a data export, or an HTML page with tables. Also applies to the table-extraction path within PDFs and DOCX files.

**How it works:**
- XLSX/CSV: `pandas` reads the file into a DataFrame. Each sheet becomes a Markdown table. Multi-sheet workbooks produce one table per sheet, with sheet names as headings. `openpyxl` is used for complex sheets with merged cells or non-standard formatting.
- JSON: Python's built-in `json` module parses the file. Arrays of objects become Markdown tables (keys as headers, values as rows). Nested JSON is flattened one level at a time; deep nesting is preserved as indented code blocks.
- XML: `lxml` with namespace stripping parses the document tree. Elements with text content become key-value pairs or table rows depending on structure.
- HTML tables: `BeautifulSoup` with `lxml` parser finds all `<table>` elements, reads `<th>` and `<td>` tags, and converts to pipe tables.

**Critical rule for structured data:** Reproduce every cell value exactly. Do not merge cells, reorder columns, or drop rows. If a value is empty, render it as an empty cell — not a dash or placeholder. Merging or reordering is a V-13 violation (Structural Invention).

**Failure modes:** Merged cells in XLSX produce incorrect column alignment when flattened. Multi-row headers require manual inspection. See `extraction-pitfalls.md` for table-specific pitfalls.

---

### 4. Format-Specific Quirks by Input Type

These are the most common format-specific issues that cause silent extraction errors. Each is covered in depth in the corresponding reference file, but the pattern to know upfront:

**PDF (text):** Page headers and footers repeat on every page — they must be detected and deduplicated before assembly. Running headers like "Chapter 3 — Methods" appearing 40 times will corrupt the Markdown if not stripped. See `extraction-pdf.md`.

**DOCX:** Styles (Heading 1, Heading 2, Normal) are the canonical structure signal — not bold/font-size. Mammoth maps them correctly. Manual bold formatting that looks like a heading is not a heading unless the style says so. See `extraction-office.md`.

**EPUB:** EPUBs are ZIP archives containing HTML files. The reading order is defined by the spine in `content.opf`. Process spine items in order, not alphabetically. Navigation document (`toc.ncx` or `nav.xhtml`) provides the heading hierarchy. See `extraction-office.md`.

**XLSX:** Formulas are stored as values after calculation. Extract the value, not the formula string, unless the user specifically asks for formulas. See `extraction-office.md`.

**HTML:** Remove nav, header, footer, sidebar, and ad elements before extracting body content. `BeautifulSoup`'s `.get_text()` on the raw page includes all boilerplate — always scope to the main content element first. See `extraction-structured.md`.

**SRT/VTT transcripts:** Strip timecodes from the Markdown output unless the user requests them. Merge consecutive same-speaker turns. Do not infer speaker names from context — reproduce only what the file labels. See `extraction-text-transcripts.md`.

## Choosing the Right Method: Decision Tree

```
Is the file a spreadsheet, CSV, JSON, or XML?
  → Yes → Structured extraction
  → No ↓

Is it a PDF?
  → Does pdfplumber return text on the first page?
      → Yes → Text-layer extraction (pdfplumber primary, pypdf fallback)
      → No  → OCR extraction (pdf2image + pytesseract)

Is it a DOCX or EPUB?
  → Text-layer extraction (mammoth for DOCX, ebooklib for EPUB)

Is it HTML or a web page?
  → Structured extraction (BeautifulSoup + lxml)

Is it a TXT, SRT, VTT, or pasted transcript?
  → Direct read with encoding detection
```

If in doubt: run the text-layer test first. If the result is empty or clearly garbled, escalate to OCR and flag the quality issue before proceeding.
