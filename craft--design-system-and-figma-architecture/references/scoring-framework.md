# Scoring Framework for Knowledge Validation

When evaluating any new resource or claim, score it against these dimensions
before accepting it into the knowledge base.

---

## The Six Dimensions

| Dimension | What It Measures |
|-----------|-----------------|
| Experience-Validity | Written from repeated practice across multiple organisations including failures. Not one success story. |
| Community Proof | Adopted by practitioners into actual work. Referenced in real system documentation. |
| Startup Applicability | Works for a team without a dedicated DS team, limited engineering runway, fast-changing product. |
| Figma-Native Relevance | Addresses Figma file architecture, variables, tokens, component structure, library management. |
| Vertical + Horizontal Scaling | Vertical: one product, more complexity. Horizontal: multiple products, brands, platforms. |
| DesignOps/EngineeringOps Bridge | Addresses where design decisions become engineering decisions. The hardest problem. |

---

## How to Use

Score each dimension 0–2:
- **0** — Not addressed or contradicted
- **1** — Partially addressed or addressed for a different context
- **2** — Directly addressed with evidence

**Threshold:** A resource scoring below 6/12 should not be added to the
knowledge base without explicit justification for why the missing dimensions
do not apply.
